使い方

はじめに（操作の流れ）

  1. 画面上部のドロップゾーン（または各映像エリア）へ動画をドロップするか、ゾーンをクリックしてファイルを選びます。２本まとめて選ぶと更新日時で左＝古い・右＝新しいと並べます（詳細は次節）。
  2. トランスポートの Video で Side by Side / Difference / Overlay、Loop で終端後のループ有無、Audio で Both / Older Only / Newer Only / Mute を選びます。
  3. Play / Pause とシークバー、またはキーボード（ページ中段のショートカット一覧）で再生位置を調整します。動画の同期ズレは Playback Drift 行で確認できます。
  4. トランスポート最下行の Export でモードと With TC を選び、Exp WebM でブラウザ内録画の WebM をダウンロードします。書き出し中のオーバレイや Esc キャンセル、出力ファイルの扱いは「書き出し（Exp WebM）とファイルについて」を参照してください。

動画の読み込みと左右の割り当て

  • 画面上部のドロップゾーンをクリックすると、ファイル選択が開きます。ここへ、またはページ上のほかの領域へドラッグ＆ドロップしても読み込めます（動画として扱えるファイルだけが対象です）。
  • 動画を２本まとめて選ぶ / ドロップした場合は、OS の最終更新日時が古いほうを左、新しいほうを右に並べます。同一時刻のときはファイル名順です。
  • １本ずつ読み込む場合は、空いている側（先に左、次に右）へ順に入ります。すでに左右がそろったあとに別ファイルを１本だけ追加すると、左だけ差し替えされ、右は未読み込みに戻ります。
  • セッションの自動復元や IndexedDB については「特記事項」を参照してください。

パネル情報・タイムコード・FPS

  • 各パネル直下の補足行には、最終更新日時、コンテナから読めたときの FPS、および尺が分かるときの総フレーム数（Total: … f）が出ます。FPS が取れない形式では FPS n/a (~60 est.) のように参考表示になります。
  • MP4 など ISO ベースのコンテナでは、先頭付近の moov / stts 等から推定した平均フレームレートを FPS に使います。
  • 各パネル映像の隅のオーバーレイは、その側の FPS に合わせた HH:MM:SS:FF です。
  • トランスポートの現在 / 総尺のタイムコード、キーボードのフレーム送り、および重ねビュー中央のタイムコードは、左右の表示 FPS の大きい方を整数化したマスター FPS に基づきます。

トランスポート（再生・シーク・各オプション）

  • トランスポート最下行の Export 欄では、プルダウンで書き出しモード（Compare PiP / Older only / Newer only）を選び、With TC で Compare 時のみタイムコードの左下焼き込みのオン・オフを切り替えます（Older / Newer のみでは焼き込み必須のため、オフにすると説明オーバレイが出てチェックはすぐオンに戻ります。閉じ方は OK・外側クリック・Esc）。Exp WebM を押すと、Audio 行で選んだモードに応じた音声をミックスした WebM を録画します（Mute 選択時や Web Audio が使えない場合は映像のみ）。Both ミックスで書き出すときは左右のデコードが必要なため、片側エクスポートでも両方のファイルが読み込まれている必要があります。Compare 書き出しは左右そろっている必要があります。書き出し中は画面中央にオーバレイが出て操作がロックされ、Esc でキャンセルできる旨と進捗が表示されます。尺ぶんリアルタイムで進みます。出力形式の注意や MP4 / MJPEG への変換は「書き出し（Exp WebM）とファイルについて」を参照してください。Chrome 系の利用を推奨します。
  • 映像の下にあるトランスポート枠は、画面上から現在 / 総尺のタイムコード → シークバーと Play / Pause → Playback Drift →（１行下のオプション条）Video → Loop → Audio → Export の順で並んでいます。オプション条の詳細は、このあとの見出しどおりです。
  • シークバーの最大値（総尺）は、左右のうち長い方の duration に合わせます。表示中の現在位置は、両要素の currentTime の遅い方（大きい方）に合わせて更新されます。
  • シークバーをドラッグしている間は、その値に応じて両方の動画へ同時にシークします。離したあと、再生中であれば更新ループが続きます。

同期、Playback Drift、自動補正

  • 同期の意味：シークや再生では、原則として両方の currentTime を同じ目標値に揃えます。デコードと描画はブラウザ任せのため、報告値がフレーム単位で常に一致するとは限りません。
  • トランスポートの Playback Drift 行は、左右の currentTime の差をミリ秒とマスター FPS 換算のフレーム数で示します。色分けは目安で、０に近いほど緑系、大きいほど赤系になります。いずれかが ended のときは ---- 表示になります。
  • 再生中にズレが約 100ms を超えた場合、短いクールダウンを挟みつつ、両方をマスター側の時刻に合わせて約１フレーム分だけ前進させる自動補正が入ります。尺の短い側が終端に張り付き、長い側だけが進んでいるときの差は「同期不良」とみなさず、補正しません。
  • 補正が走ると、ログに Sync auto-correct: … が間欠的に残ります。
  • Video の Difference モードでは、重ねた２本の画素が一致している領域は差分がゼロとなり、画面は真っ黒に見えます。変化や不一致がある箇所だけが、差分として色付きで浮かび上がります。この見え方は「同一時刻の同じフレーム同士」を重ねている前提に強く依存するため、同期がわずかにでもズレていると、実質同じ内容でも前後のフレーム差として広く差分が出て、Difference の見え方が大きく変わります。Playback Drift の表示や自動補正は、そのズレを抑え、差分表示を読みやすく保つための目安・調整です。

映像レイアウト（Video）

  • トランスポート内の Video プルダウン、または [V] で、次の３モードだけをこの順に循環します。Side by Side（左右並び）→ Difference（差分重ね）→ Overlay（新しい側を上に、不透明度およそ 75% で重ねる）→ 先頭へ戻る、の繰り返しです。プルダウンの値と [V] は常に連動します。
  • Side by Side：左が古い動画、右が新しい動画の２パネル表示（既定）。ファイル名・補足行・隅のタイムコードの意味は、上の「パネル情報・タイムコード・FPS」と同じです。
  • Difference / Overlay：同一タイムライン上の２本を１画面に重ねます。下が左（古い方）、上が右（新しい方）です。Difference は CSS の mix-blend-mode: difference、Overlay は上層（新しい側）に opacity: 0.75（およそ 75% 不透明）を当てたうえで通常合成し、下の画との差を見やすくします。左右パネルは隠れ、合成ビューだけが表示されます。
  • 重ねモードでは、オーバーレイのタイムコードはトランスポートと同じマスター FPS（上記「パネル情報」）で、Side by Side 時より大きめの字体です。レイアウト切り替えは再生中でも可で、通常は再生が継続します。
  • 差分はブラウザの合成に依存するため、圧縮ノイズ・解像度差・トリミングのズレがあると、実質同じ内容でも差が広がって見えることがあります。

ループ再生（Loop）

  • Loop にチェックが入っているとき（既定）：長い方の尺の終端に達すると、両方の再生位置を先頭付近へ戻し、再生を継続します（各 video 要素の loop 属性ではなく、アプリ側で両者を揃えて再開しています）。
  • チェックを外したとき：終端で一時停止し、トランスポートが止まります。
  • On / Off はトランスポートのチェックボックスか [L] です。

音声出力（Audio）

  • トランスポートのラジオボタン、または [B] / [O] / [N] / [M] で切り替えます。ログや一時ヒントには、内部的な説明付きで Both (Mono + Pan)、Older Only (Stereo)、Newer Only (Stereo)、Mute と出ることがありますが、UI ラベルは Both、Older Only、Newer Only、Mute です。
  • Both：各動画の L/R を 0.5 倍して足し合わせてモノラル化し、古い方を L、新しい方を R にパンして出力します。
  • Older Only：左（古い方）のステレオをそのまま L/R に出力します。
  • Newer Only：右（新しい方）のステレオをそのまま L/R に出力します。
  • Mute：無音です。WebM 書き出し時も音声トラックは付けず映像のみになります。

書き出し（Exp WebM）とファイルについて

  • 本アプリの Exp WebM は、ブラウザの MediaRecorder と canvas.captureStream、および Web Audio で得た音声（Mute 時は映像のみ）を組み合わせて、WebM（主に VP8 / VP9 系＋必要に応じて Opus）をその場で生成しダウンロードします。編集・納品の現場では MP4（H.264 等）や MJPEG など別形式に慣れている方も多く、WebM 単体では馴染みが薄い形式かもしれません。
  • MP4 や MJPEG など別コンテナへ変換したい場合は、お手数ですがご利用の OS 向けの動画変換ツールやエンコーダを別途ご用意ください。本ページはサーバーにアップロードせずブラウザ内だけで完結するアプリであり、ブラウザが直接書き出せる形式に出力が限られることは仕様です。一般的な編集ソフトのプリセットだけではなく、想定ワークフローに合わせて変換段階を設けていただく必要があり、ご不便をおかけしますことお詫び申し上げます。
  • WebM を他形式へ再エンコードするとき、色空間・ガンマ・レンジ（limited / full 等）の扱いをツール側で誤ると、結果が意図より暗くなったりコントラストがずれたりすることがあります。変換プリセットや「色の管理」「レンジ」の項目は、利用するソフトのマニュアルで確認してください。

シーク・操作の画面上ヒント

  • 矢印キーやテンキーのジャンプ、レイアウト / 音声 / ループの変更などのあと、画面上部に短いテキストのフラッシュが出ることがあります。ログとあわせて、直近の操作内容の確認に使えます。

キーボードショートカット

  • 再生・シーク・音声・レイアウト・ループなどにショートカットがあります。内容はページ中段の一覧どおりです。
  • 無効になるフォーカス：textarea、select（Video のプルダウン含む）、input のうちシークバー（type="range"）以外、ならびに contenteditable 要素にフォーカスがある間は、ショートカットは処理されません。シークバーにフォーカスがある場合は、主要なショートカットキーを押すとフォーカスが外れてから処理されます。
  • 矢印キーは連打リピート時もシークに使えます。その他の多くのキーはリピートを無視します。

ソースコードを改変する場合

ソースの読み方と、ブラウザへの保存（キーとフィールド）

  • スクリプト先頭（<script> 直後の IIFE 内）に、読み順と改造しやすい定数・関数の目安をまとめたブロックコメントがあります。大きな処理は // === 数字. で始まる区切りコメントでブロック化してあるので、エディタで === を検索するとたどれます。映像レイアウト・ループ・音声の UI はトランスポート付近の HTML と、同ファイル末尾の <script> 内の状態・イベント処理が中心です。
  • ここでいう「保存」は、タブやブラウザを閉じたあとも端末内のブラウザ領域に残し、次にこのページを開いたときに読み戻す、という意味です。サーバーへ送る処理はありません。小さな UI 状態は localStorage、動画ファイルのコピーは容量の大きい IndexedDB に分かれています（下記）。
  • localStorage（キー定数 LS_PREFS_KEY、既定 mp4_compare_prefs_v1）: writePrefs が JSON １本で書き込みます。フィールドは audioMode（split-mono / old-stereo / new-stereo / mute）、transportTime（シーク位置・秒）、viewMode、loopPlayback、exportMode（compare-pip / solo-old / solo-new）、exportBurnTc（真偽）です。読み出しは readPrefs、起動直後の反映は initPrefsFromStorage です。IndexedDB へセッションを書く直前にも writePrefs が呼ばれます。キー文字列を変えると、以前の保存とは別レコードとして扱われます。
  • IndexedDB（データベース名 IDB_NAME、既定 mp4_compare_session_v1、バージョン IDB_VER）: オブジェクトストアは IDB_STORE（既定 kv）の１つだけで、最後に保存したセッションはキー IDB_KEY_LAST（既定 lastSession）に put されます（schedulePersistSession → persistSessionToStorage）。値は v: 1 と、左右にファイルがあれば lName / lm / lBlob、rName / rm / rBlob、あわせて audioMode / transportTime / viewMode / loopPlayback を含みます。書き出し欄の exportMode / exportBurnTc はこのレコードには含めず、上記 localStorage のみです。左右とも動画が空の状態で保存しようとすると IDB_KEY_LAST は削除されます。ストアの形を変えるときは IDB_VER を上げ、openIdb 内の onupgradeneeded でストア作成に対応してください。
  • オプションの「映像」「ループ」「音声」「Export」をそれぞれ別ブロックとして発行・埋め込みしたい場合は、HTML の transport-opt-box--view / transport-opt-box--loop / transport-opt-box--audio / transport-opt-box--export を起点に分割すると追いやすいです。関連する要素 ID（viewModeSelect、loopPlaybackCheckbox、audioMode ラジオ群、exportModeSelect、exportBurnTcCheckbox、exportPipBtn、exportBlockingOverlay、exportBlockingSub、exportBlockingEscHint、soloTcNoticeOverlay、soloTcNoticeOk）はスクリプトから参照されているため、ID を変える場合はスクリプト側も合わせて更新してください。

WebM 書き出しを改変する場合

  • 録画の核は runSilentWebmExport（pipExportCanvas.captureStream、MediaRecorder、pickWebMRecorderMimeType(withAudio)）です。書き出し中は pipExportActive が真になり、exportBlockingOverlay / exportBlockingSub で進捗を表示します。Esc キャンセルは tryCancelSilentWebmExportFromEsc と currentExportRecorder を参照してください。
  • 音声ミックスは ensureWebAudioRouting → buildAudioGraph(mode, outputNode) で、通常再生は audioCtx.destination、書き出し中は一時的に createMediaStreamDestination() へ切り替え、終了時に restorePlaybackAudioRouting で戻します。input[name="audioMode"] の value に mute を足す場合は getAudioMode / applySavedAudioToRadios の許可配列も忘れずに。
  • コンテナやコーデックをブラウザ外で変えたい場合は、本アプリではなく変換パイプライン側の実装になります（使い方「書き出し（Exp WebM）とファイルについて」参照）。
